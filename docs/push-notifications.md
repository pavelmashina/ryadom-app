# Web Push в PET APP / «Рядом»

## Реализованная архитектура

- `push_subscriptions`: один пользователь может зарегистрировать несколько устройств; подписки отделены от общих данных питомца, действуют политики RLS `user_id = auth.uid()`.
- `event_reminders`: персональные интервалы и `enabled` для каждой пары пользователь/событие. Несколько строк на событие допустимы.
- `notification_deliveries`: логические задания, уникальный ключ `(user_id,event_id,occurrence_at,reminder_id)`.
- `notification_device_deliveries`: фиксирует отправку на конкретное устройство, чтобы повторная попытка не отправляла ещё раз уже обработанной подписке.
- `push_public_config`: открытый VAPID-ключ, доступный из frontend. **Закрытый ключ не хранится в репозитории и не выдаётся пользователям.**
- `pet-push-worker`: Supabase Edge Function с проверкой секретного токена из Vault перед обработкой; подпись и шифрование Web Push через `jsr:@negrel/webpush@0.5.0`.
- `pg_cron` + `pg_net`: вызов worker раз в минуту. Токен берётся из `vault.decrypted_secrets`, а не сохраняется непосредственно в SQL задания.

## Секреты

На текущем production-проекте `vbnkziodmyykyazdcrwl` настроены два значения Supabase Vault:

- `pet_vapid_private` — закрытый P-256 VAPID-ключ.
- `pet_push_cron_token` — случайный токен, которым cron авторизует запросы.

**Не копировать значения этих секретов в Git, Actions, переменные VITE_ или клиентскую сборку.** При развёртывании в новом проекте необходимо сгенерировать новую пару VAPID и новый токен, создать записи Vault и поместить соответствующий открытый ключ в `push_public_config`. Не переносить private key через SQL-миграции.

## Проверка запуска

1. Проверить Supabase Functions → `pet-push-worker` (должен быть ACTIVE).
2. Проверить `cron.job` с именем `pet-push-worker-every-minute`.
3. Проверить ответы `net._http_response`: успешный пустой запуск отвечает `200 {"queued":0,"processed":0}`.
4. Проверка VAPID через авторизованный запрос `?selftest=1` возвращает `200 {"vapid":"ready","authenticated":true}`. Не запускать без токена.
5. На iPhone/iPad установить PWA на экран «Домой» (iOS 16.4+), открыть приложение и нажать «Включить уведомления» в аккаунте.
6. В карточке события сохранить **Моё напоминание**. Дождаться времени и проверить фактическую доставку на устройство.
7. После удаления подписки и выхода из аккаунта push на соответствующее устройство больше не должен отправляться.

## Тестирование

До релиза проверены: SQL-расчёт периодичности, сохранность истории тренировок, генерация задания в транзакции с откатом, проверка неверного cron-токена, VAPID selftest, успешные пустые запуски cron, CI тесты и сборка. **Фактическая доставка на реальный iPhone/Android/desktop не подтверждена без участия устройства.** Переходы DST проверять отдельно для временных зон с сезонным переводом часов.

## Ограничения

- Сама отправка push зависит от Apple/Google/Mozilla push service, интернет-соединения и разрешений ОС. «Ровно один раз» гарантируется на уровне задания и регистрации доставки устройству, но транспорт не гарантирует строго единственного показа при аварии после внешней отправки.
- Пока персональные настройки UI находятся в карточках общих событий/напоминаний. Отдельная настройка push именно для каждого автоматически сформированного занятия в разделе «Занятия» — дальнейшее улучшение.
