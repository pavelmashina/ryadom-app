## Общие компоненты

`src/components.tsx`: Button, IconButton, Card, InteractiveCard, Badge, PageHeader, SectionHeader, Modal, Input (совместимый псевдоним Field), Select, Textarea, Checkbox, Form, Empty. Note использует Textarea.

- Button: primary для главного действия, secondary для дополнительных, ghost для ненавязчивых, destructive для опасных. Размеры sm/md/lg, fullWidth, hover/active/focus/disabled/loading. По умолчанию type=button; отправка формы явная. Загрузка блокирует повторное действие.
- IconButton: доступное название, одинаковая область нажатия, иконка по центру. Все крестики используют его.
- Card: обычная и информационная. InteractiveCard — настоящая кнопка с фокусом и стрелкой, поэтому интерактивность заметна и доступна с клавиатуры.
- Modal: native dialog, заголовок, одинаковый крестик, содержимое; Form задаёт область действий. Escape, возврат фокуса, блокировка фоновой прокрутки, ограничение высоты через dvh и safe-area. Во время сохранения закрытие заблокировано.
- Поля имеют связанные подписи, подсказки и сообщения ошибок, единые рамки и фокус. Checkbox имеет увеличенную область нажатия. Form защищён от двойной отправки и сообщает об ошибках/сохранении.

Старые нативные кнопки и поля на экранах заменены общими компонентами. Удалено независимое оформление авторизации и постоянная плашка email/выхода. Стили экранов сведены к общей шкале.

## Аккаунт и Supabase Auth

Иконка аккаунта находится в верхней панели. Раздел показывает email и доступную дату регистрации. Расширяемый AccountSection объединяет «Вход и безопасность» и «Сеанс».

- GET `/auth/v1/user` обновляет данные пользователя при открытии раздела.
- PUT `/auth/v1/user` с email отправляет запрос изменения и redirect_to на опубликованное приложение. До подтверждения показывается прежний email; pending new_email выводится отдельно. Пользователю предложено проверить оба почтовых ящика.
- PUT `/auth/v1/user` с password/current_password меняет пароль. Форма проверяет текущий пароль на заполненность, новый — минимум 8 символов, повтор — на совпадение. Ошибки сервера и необходимость повторного входа отображаются пользователю.
- Выход использует существующий signOut и очищает текущий интерфейс аккаунта.
- Все запросы идут с пользовательским access token и публичным ключом. Admin/service-role ключи не добавлялись. Перед записью метаданных проверяется идентичность аккаунта, включая запоздалые ответы. Пароли не сохраняются в localStorage.
- После email confirmation callback токены удаляются из адресной строки, существующий аккаунт не подменяется. Подтверждение выполняет Supabase; актуальный email загружается при открытии аккаунта.

## Проверки и границы проверки

- 84 автоматические проверки: существующие сценарии данных, облачного сохранения и восстановления; новые сценарии аккаунта, валидации, изоляции пользователей, callback и доступной разметки компонентов.
- Production build: TypeScript и Vite.
- В браузере: 5 основных экранов × ширины 320/390/430 px. Горизонтального переполнения страницы не обнаружено. Заголовки используют Manrope.
- Форма пароля на 320 px помещается; поля 16 px, крестик 44 × 44 px. Escape закрывает диалог и возвращает фокус на кнопку открытия.
- На изолированных тестовых данных создана тренировка с двумя командами и комментарием, проверены сохранение и просмотр результата. Перезагрузка сохраняет сеанс, выход возвращает экран входа. Ошибок консоли не обнаружено.
- Реальные email/пароль владельца не изменялись. Auth-проверки изменения данных используют подменённые HTTP-ответы; реальная доставка писем и смена учётных данных не являются пройденным сквозным тестом.
- SMTP этой задачей не настраивался: встроенная почта Supabase ограничена адресатами/частотой. Для произвольных пользователей нужна собственная доставка. Текущие Site URL/Redirect URL указывают на Pages.
- Повторная проверка Supabase Security Advisor показала прежнее предупреждение о выключенной leaked-password protection; новых изменений БД нет. Эта защита доступна на платных планах. [Документация](https://supabase.com/docs/guides/auth/password-security).

Мобильные размеры проверены в браузерном viewport; отдельный запуск на физическом iPhone в этой ревизии не выполнялся.
